# 11. Idempotency

This is mandatory.

Kafka consumers must be **idempotent**.

For example, if:

```text
expense.created
```

is delivered twice, the Ledger Service must NOT create two ledger entries.

Create an event processing mechanism such as:

```text
processed_events
```

with:

```text
event_id
consumer_name
processed_at
```

Before processing an event:

```text
if event already processed:
    ignore event
else:
    process event
    mark event processed
```

Use a unique constraint on the appropriate columns.

Explain why Kafka provides at-least-once delivery and why application-level idempotency is therefore required.

# 12. Retry Mechanism

Implement retries for Kafka consumers.

Example:

```text
Attempt 1
   ↓
failure
   ↓
Attempt 2
   ↓
failure
   ↓
Attempt 3
   ↓
failure
   ↓
DLQ
```

Use Spring Kafka's retry/error handling mechanisms where appropriate.

Configure:

```text

```

Use reasonable backoff.

For example:

```text
1 second
2 seconds
4 seconds
```

Do not implement a custom retry framework unless necessary.

# 13. Dead Letter Queue

If a message cannot be processed after retries, publish it to a DLQ.

Example:

```text
expense.created
       │
       ▼
Consumer
       │
       ├── success ──► Ledger
       │
       └── failure
             │
             ▼
           Retry
             │
             ▼
          3 attempts
             │
             ▼
        expense.created.DLT
```

Configure and explain:

* Why the message failed
* Retry count
* Original topic
* Partition
* Offset
* Exception information

Make DLQ handling observable through logs.

# 15. Transactional Outbox

Implement an Outbox table in the Expense Service:

```text
outbox_event
----------------
id
aggregate_id
event_type
payload
created_at
published
```

When creating an expense:

```text
BEGIN TRANSACTION

INSERT expense

INSERT outbox_event

COMMIT
```

Then a publisher component reads unpublished outbox events and publishes them to Kafka.

This prevents the major problem where the expense is successfully saved but the Kafka event is lost.

Explain the trade-offs and limitations.
